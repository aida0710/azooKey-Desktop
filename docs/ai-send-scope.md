# AI に渡す本文と送信先

通常のかな漢字変換は端末内で処理します。AI 変換は設定した外部 API、または対応する Mac の Foundation Models を使います。

macOS の AI 操作では、送信前に「送信先」「対象の本文」「周辺テキストを含める」を確認できます。外部 API の表示はホスト名とポートだけです。カスタム URL のユーザー名、パスワード、パス、クエリは表示しません。確認画面を開いたときの接続設定を、その送信に使います。

周辺テキストの初期値はオフです。オンにすると対象の前後それぞれ最大 100 文字を含めます。既存の選択は保持し、確認画面で変更した値を次回にも使います。指示の履歴へ保存するのは指示文だけで、対象の本文と周辺テキストは含みません。

## macOS の操作

- 入力中に AI 候補を呼び出すと、入力欄のフォーカスを保った確認パネルが開きます。Control+S で送信、Control+Shift+S で周辺テキストの設定を切り替え、Escape で確認だけを取り消します。ボタンでも操作できます。
- 確認中や通信待ちの Enter は、元の未確定入力を確定します。通常の文字入力を続けると確認・要求を取り消します。
- 選択した本文の変換は、指示、送信先、対象の本文を確認して「AI へ送信してプレビュー」を押します。保存済みの指示や翻訳ショートカットから開いても、開いただけでは送信しません。
- プレビューで失敗した場合はエラーを表示し、その文字列を本文へ適用しません。
- 再生成を始めた時点で前回のプレビューは適用できなくなります。指示や周辺テキストの設定を変えた場合、変更前の要求が後から完了しても表示・適用しません。
- 適用時は元の入力欄への復帰を待ち、選択範囲と本文が変わっていない場合だけ一度置き換えます。本文・範囲・入力欄が変わった場合や確認できない場合は文書を変更せず、「結果をコピー」から利用者が貼り付け先を選べます。

## 検証

`AIRequestScopeTests` は URLSession の模擬応答で実際の JSON 本文を取得します。周辺テキストをオフにすると前後の識別用文字列が本文全体から外れ、オンでは含まれることを、候補要求と選択文変換の両方で確かめます。外部サービスへの通信はありません。

`AISuggestionInputTests` は遅延する AI と InputMethodKit の模擬クライアントを使います。送信前に通信が始まらないこと、確認中の Enter、キーボードでの取消・設定変更・送信、設定が変わっても表示済みの送信先を使うことを確かめます。

`AITransformationPreviewTests` は、再生成中、指示変更、失敗・空の応答、応答順序の入れ替わりで古い本文が適用可能にならないことを確かめます。実際の Enter 操作は実機確認に含めます。

`SelectedTextReplacementTests` は、元の入力欄・UTF-16 の選択範囲・取得できた実範囲・本文が一致した場合の一度だけの置換と、不一致・読取失敗・取消・同期読取中のフォーカス変更で挿入しないことを検査します。`SelectedTextTransformTests` は模擬 IMK クライアントでフォーカス復帰を通知し、`PromptInputWindowTests` は適用と取消の完了が一度だけ通知されることを検査します。これらは外部 AI へ接続しません。

実機では TextEdit と Chromium 系アプリで、長い対象本文の表示、入力フォーカス、確認中・通信待ちの Enter、入力欄やアプリの切替を確認します。選択した「前日本語後」の「日本語」だけが一度置換されること、同じ本文がある別の欄・別のアプリや、プレビュー中に編集した本文へ旧結果が適用されないことも確認します。拒否時のコピーは利用者が選んだときだけ行い、元の文書は変わらないことを確認します。VoiceOver で送信先・対象・周辺設定を読めることも確認が必要です。単体テストの `canBecomeKey == false` は、この実機確認の代わりにはなりません。
