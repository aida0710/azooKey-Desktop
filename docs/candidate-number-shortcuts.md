# 候補番号と数字キー

候補の `1.`〜`9.` は、数字キーでその候補を確定できる状態だけに表示する。
候補一覧の「現在位置 / 総件数」は操作の割り当てではないため、引き続き表示する。

| 入力状態 | 候補番号 | 数字キー | ポインターでの選択 |
| --- | --- | --- | --- |
| 通常の候補選択 (`selecting`) | 表示 | 現在のページの実候補を確定 | 実候補を確定 |
| AI提案 (`replaceSuggestion`) | 非表示 | 元の読みに数字を追記 | AI提案の実候補を確定 |
| 入力中・プレビュー | 非表示 | 既存の入力処理に従う | 表示中の実候補を選択 |

Linux の GTK と GNOME Shell は `DesktopSnapshot.showCandidateIndex` を、ツリーの番号と全候補一覧の接頭辞の両方に使う。`DesktopSession.snapshot()` は `selecting` のときだけこの値を有効にする。AI提案の数字入力に対する `InputState` の動作は変更しない。

macOS の通常候補は `CandidatesViewController.showCandidateIndex`、AI提案は番号を付けない `ReplaceSuggestionsViewController` を使う。通常候補一覧も、番号の指定が空になったら行を更新して接頭辞を消す。

## 回帰試験

- Core: ライブ変換とツリー表示の各 ON/OFF で、通常候補の番号が表示され、AI提案の複数ページでは非表示になる。AI提案中に `1` を押すと元の読みに `1` が加わり、提案を確定しない。その後のポインター操作では指定した提案を一度だけ確定する。
- GTK: 実 Swift bridge に固定の AI提案を渡す。通常候補から切り替えると、ツリーの番号と一覧の接頭辞が消える。ページを移っても番号を表示せず、数字入力とクリック確定の結果、元の入力欄のフォーカスを確認する。
- macOS: AppKit 回帰で同じ候補の番号を表示→非表示へ切り替え、AI専用ビューの行に番号がないことを確認する。Linux の構文確認は macOS 実行結果の代わりにはならない。
- GNOME Shell: `extension.js` のツリー番号と `candidateNavigation.js` の一覧接頭辞が同じフラグで制御されることを静的確認する。実デスクトップでは AI提案を開き、番号がないこと、数字が元の読みに残ること、ページ移動後のクリックが表示した提案を確定することを確認する。

実デスクトップや VoiceOver / Orca の確認を、構文検査や GTK 部品の試験だけで完了扱いにしない。
