# 設定と AI 操作の用語・操作

設定は macOS と Linux の両方で次の分類に揃える。既存の保存キーと値は変更しない。

| ページ | 設定 |
| --- | --- |
| 入力 | 入力配列、記号、カスタム入力表 |
| 変換表示 | 候補表示、文字サイズ、ライブ変換、推論上限、開発中の変換機能 |
| 辞書と学習 | ユーザー辞書、履歴学習、変換プロフィール、個人化モデル |
| AI | AI の種類、モデル名、接続先、API キー、周辺テキスト、ショートカット |
| サポート | 初回案内、復旧、更新、診断情報 |

macOS は標準の `TabView`、Linux は標準の `Gtk.Notebook` を使い、選択状態を各プラットフォームへ公開する。変換プロフィールは一か所にまとめ、個人化モデルは履歴学習と同じページへ移す。履歴学習・プロフィール・個人化モデルの違いもページ内で説明する。

## 用語

| 概念 | 表示 |
| --- | --- |
| AI による本文の変換 | AI変換 |
| 外部 API を使う AI の種類 | OpenAI互換API |
| リクエストを送る URL | APIの接続先URL |
| AI に渡す指示文 | AIへの指示 |
| 保存した指示文 | 指示の履歴 |
| 送信して結果を取得する操作 | AIへ送信してプレビュー |
| 生成した本文を確認する表示 | プレビュー |
| 確認した本文を元の入力欄へ反映する操作 | 本文へ適用 |
| 指示や確認を閉じる操作 | 取消 |
| 通常変換へ渡す補足情報 | 変換プロフィール |
| 別途作成した個人化のモデル | 個人化モデル |

新しい表示文言は Core の日英カタログと Linux の日本語カタログに置く。同じ設定・操作では同じキーを使う。既存の指示履歴は翻訳したり書き換えたりしない。

## キーボードと支援技術

- Linux のラベルは入力欄と相互に関連付け、Entry・ComboBox・TextView へ名前を公開する。AI 画面の指示欄・履歴・ショートカットには mnemonic も付ける。
- macOS のショートカット記録欄は、ボタンの役割・名前・登録値・記録中の状態・操作説明を公開する。Tab / Shift+Tab は次 / 前の項目への移動に使い、ショートカットとして登録しない。
- AI 履歴は標準ボタンで選ぶ。選択だけでは送信せず、内容を確認してから Enter または送信ボタンを使う。取消は Escape で行える。
- プレビュー取得中・空応答・失敗時は適用できない。指示や送信範囲の変更は前のプレビューを無効にする。遅れて届いた前の応答も適用しない。
- 保存エラーは画面へ残し、Linux は ATK の alert、macOS は既存の表示に加えてアクセシビリティ通知を使う。名前や通知の存在を、実際の読み上げ確認の代わりにはしない。

## 自動試験と残る確認

Ubuntu 24.04 の専用コンテナで、GTK のラベル関連・タブの選択状態・Tab 移動・保存エラーとファイル維持・明示送信を確認する。設定・AI 送信範囲・同時プレビュー・診断・実 Swift bridge を使う設定保存を合わせた 53 回帰が成功した。Xvfb の画面は構造の確認用で、実アプリや読み上げの受入証跡ではない。

macOS にはショートカット記録欄の実 AppKit 回帰を追加した。Linux 上の構文検査は成功しているが、macOS でのビルド・実行結果は CI で確認する必要がある。

最終統合したパッケージでは、以下を別途確認する。

1. VoiceOver / Orca を有効にして、各欄の名前・現在値・選択中タブ・保存エラーが読まれること。
2. キーボードだけで設定変更、辞書追加・保存、AI の送信・取消・適用を行えること。辞書の新しい編集画面は #11 / #12 の統合後に確認する。
3. 元のアプリで本文を選び、AI 画面で取消した場合は本文が維持され、適用した場合は確認済み本文だけが反映されること。
4. 設定ページ移動・保存・再起動後も、入力配列、候補サイズ、学習モード、プロフィール、個人化、AI 接続設定が保持されること。
