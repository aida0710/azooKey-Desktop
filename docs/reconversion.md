# 確定取消と選択再変換

## 操作

| 操作 | キー | 文書への作用 |
| --- | --- | --- |
| 候補選択を戻す | Escape | 候補選択から読みの入力へ戻ります。通常入力では、さらに Escape を押すと入力中の文字を取り消します。 |
| 直前の確定を取り消す | Ctrl+Shift+Backspace | azooKey で直前に確定した文字を未確定へ戻し、元の読み・ローマ字入力・候補選択を復元します。 |
| 選択した文字を再変換 | Ctrl+Shift+R | 文書内の選択文字列を、通常辞書の候補から選び直します。 |
| 文書全体の編集を戻す | アプリの「元に戻す」 | アプリが持つ編集履歴に従います。azooKey の確定取消とは別の操作です。 |

確定取消と選択再変換は、入力メニューからも実行できます。先に入力中の文字を確定してください。

Linux では IBus の入力メニューから選び、元の入力欄で Enter を押すと開始します。Enter を押すまでは文書を変更しません。Esc で取り消せます。ほかの文字や移動キーを押すと、再変換を取り消して通常の入力として処理します。ショートカットからは追加の Enter なしで開始します。

確定取消が使えるのは、同じ入力先・同じ文書位置で、確定した文字と周辺の文字が変わっていない場合です。新しい変換入力、フォーカス移動、入力のリセットで履歴を破棄します。履歴は一件だけをメモリに保持し、保存しません。

## 読みが分からない選択文字列

選択がかなの場合は、その読みを使います。ユーザー辞書に表記が一致し、読みが一意に決まる項目がある場合も、その読みを使います。それ以外は「読みを入力」と表示します。

この間は元の文書と選択範囲を保持します。ローマ字で読みを入力し、Enter で再変換を開始してください。Backspace で読みを修正し、Escape で中止できます。入力先を変えたり、選択文字列を変更した場合も中止します。外部 AI への送信は行いません。

再変換後に Enter で候補を確定すると、元の選択範囲をその候補で置き換えます。Escape を押して候補選択、読み入力の順に戻り、入力を取り消すと元の表記を一度だけ復元します。ライブ変換の設定により候補表示の段階が異なります。

再変換では範囲全体の候補を選んでください。元の表記と読みを部分ごとに対応付ける情報がないため、文節の縮小後などの部分確定は拒否し、元の文字列を取消用に保持します。

## 入力先による制限

周辺文字列と選択範囲を読めない入力先、保護された入力先、読み取り専用の入力先では、再変換を利用できません。確認できない範囲を推測して削除しません。

macOS は IMK の範囲指定による未確定文字への置換を使い、置換後の文字を読み戻して確認します。Ubuntu は IBus の削除通知を送り、入力先から周辺文字列の更新が届いた後に、未確定文字を復元します。更新が届かない場合は削除を繰り返さず、置換を確認できない旨を表示します。

IBus の削除通知は成功・失敗を返しません。削除直後に入力先が閉じる、または更新通知を失う場合には結果を確認できないため、別の入力先へ元の文字を挿入しません。この境界とアプリ自身の「元に戻す」の挙動は、実アプリでの確認が必要です。

## 検証

共有 Core は、範囲の一致、変更された周辺文字列、保護された入力、取り消された要求、非 BMP 文字・結合文字、元のローマ字入力、部分確定の拒否、読み入力中の文書保持を回帰試験で確認します。

macOS の模擬 IMK クライアント試験は `azooKeyMacTests/ReconversionInputTests.swift`、Linux の非同期処理試験は `Linux/tests/test_reconversion.py`、実 IBus の固定文書試験は `Linux/tests/ibus_reconversion.py` です。

実アプリの検証では次を記録してください。

1. macOS の TextEdit とブラウザー、Ubuntu VM の GTK・Qt・Chromium で、同音異義語の確定取消と選択再変換を行う。
2. 再確定・Escape・アプリの「元に戻す」をそれぞれ試し、重複・消失がないことを確認する。
3. 読み入力中と削除確認中に、選択変更、別の入力先への移動、読み取り専用化を試す。
4. 入力先・コミット・パッケージ版・表示サーバーを証跡に記録する。Xvfb、模擬クライアント、自動試験の成功だけで実アプリや VoiceOver・Orca の確認済みとはしない。
