# 候補の相対スコア

候補の下の数値は、変換器が返した候補を比べるための相対値です。正解の確率や、全文の信頼度を表す数値ではありません。計算式と丸め方は既存のままです。

設定の「相対スコアを表示」で、数値とその表示領域を隠せます。既定は表示です。非表示でも、選択された経路・操作対象・候補番号・確定結果は変わりません。語の選択色とスコアの色は別に扱い、未評価を高評価の色へ置き換えません。

## 数値を読む

- 比較するのは、全文の読みと消費する入力範囲が同じ取得候補です。別の範囲を確定する候補は混ぜません。
- 同じ全文表記の重複は、最も高い評価を持つ一候補にまとめます。
- 画面に今は見えていない兄弟候補も計算に含みます。
- 子の数値は、その親から分岐する候補同士の比較です。親が 1 でも、その親の子が一つなら子は 100 になります。100 は正解の保証ではありません。
- 0 は丸めた相対値です。その候補が不可能という意味ではありません。
- 「—」は未評価です。同じ読み・入力範囲で比較できる評価がなく、0 とは区別します。

例えば、同じ条件で評価が等しい四候補があり、画面に三候補だけ表示されている場合も、各候補は 25 です。同じ表記の候補がもう一件あっても重複分を加算せず、別の入力範囲で非常に高い評価の候補があっても混ぜません。

## 説明への移動

スコアを表示しているときは、矢印キーで操作する候補を移すと、詳細欄にその候補のスコアと意味を表示します。PageUp / PageDown で詳細をスクロールできます。マウスで候補に重ねても同じ説明を読めます。これらの操作で候補ウィンドウが文書のフォーカスを奪うことはありません。

説明文字列は Core の `CandidateScorePresentation` が作り、Linux の GTK/GNOME には候補と一緒に渡します。macOS も同じ説明を使います。描画側はスコアの計算や候補の合成をしません。

## 回帰検査

Core の固定候補試験で、低い親と唯一の子、0 と未評価、一候補だけの場合、隠れ兄弟・同一表記・異なる消費範囲を検査します。実 bridge では表示の切替後と再起動後の設定保持、候補と読みの維持、元の候補が一度だけ確定することを確認します。

GTK と AppKit の部品試験では、表示切替による詳細・領域の変更、操作対象の保持、非フォーカスと一度の確定を確認します。これらは実アプリや VoiceOver/Orca の読み上げ確認を代替しません。
