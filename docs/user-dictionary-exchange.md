# ユーザー辞書の移行とバックアップ

ユーザー辞書の画面で、読み・単語・ヒントを検索し、列見出しで並べ替えられます。検索や並べ替えの後も、選んだ項目のIDで編集します。Linuxの「登録順に戻す」で元の順番へ戻せます。

編集と取込は下書きに対する操作です。「保存」で入力検証、辞書作成、設定の保存、変換器の再読込みを行います。画面をキャンセルすると、未保存の編集と取込を破棄します。保存に失敗した場合は理由を表示して下書きを残します。以前の辞書への復元にも失敗した場合は、再保存を止めて確認を促します。

## 対応する形式

| 形式 | 読込 | 書出し | 条件 |
|---|---|---|---|
| azooKeyユーザー辞書JSON v1 | 対応 | 対応 | 読み・単語・ヒントを保持するバックアップ形式 |
| ATOK 2017の公開単語テキスト | 対応範囲を限定 | 未対応 | `!!ATOK_TANGO_TEXT_HEADER_1`ヘッダーが必要 |
| Mozcの辞書テキスト | 対応範囲を限定 | 未対応 | 読み・単語・品詞をタブで区切る。4列目はヒントとして扱う |
| ATOK独自バイナリ・旧形式 | 未対応 | 未対応 | テキストの公開仕様とは別の形式 |

文字コードの自動判定はUTF-8とBOM付きUTF-16に限ります。Shift_JISは明示して選びます。不正な文字列を置換文字で修復して取り込む処理は行いません。

テキスト形式の品詞は、実装で列挙した名詞・固有名詞だけを受け付けます。現在の辞書作成処理では、受け付けた語を固有名詞として登録します。この扱いをプレビューに表示します。活用語、未対応の追加フィールド、不正な読みなどは、行と理由を示して除外します。タブと改行を含むヒントを可逆に持ち出す場合はJSONを使ってください。

ATOK形式の根拠は[JustSystemsのATOK 2017単語ファイル仕様](https://support.justsystems.com/faq/1032/app/servlet/qadoc?QID=056444)、Mozc形式の根拠は[Mozcの公式取込処理](https://github.com/google/mozc/blob/master/src/client/user_dictionary/user_dictionary_importer.cc)です。実際のATOK製品で書き出したファイルの往復は未検証です。自動試験には公開仕様に沿って作った合成データを使います。

## 取込前に確認する内容

プレビューには追加・重複・衝突・除外の件数と、各行の結果を表示します。

- 読みはひらがな／カタカナを同一とみなして比較します。保存する読み自体は書き換えません。
- 読みと単語が一致し、ヒントも同じ場合は重複です。空のヒントとヒントなしは同じとみなします。
- 読みと単語が一致し、ヒントが違う場合は衝突です。既存項目を優先し、上書きしません。
- 新たな項目を下書きへ追加します。取込後も「保存」までは変換に反映しません。

プレビューを取り消しても下書きは変わりません。プレビュー作成後に元の下書きが変わった場合、そのプレビューを適用しません。書出しも下書きを対象にでき、書き出しただけで辞書を保存済みにはしません。

## JSON v1

UTF-8で次の構造を書き出します。項目のIDは交換せず、読込先で作成します。

```json
{
  "format": "azookey-user-dictionary",
  "version": 1,
  "items": [
    {"reading": "てすと", "word": "試験用語", "hint": "タブ\tと改行\nを保持"}
  ]
}
```

ヒントの省略と空文字を区別して保持します。生の読み・単語・ヒントにUnicode正規化を適用しません。書出し先は一時ファイルから置き換え、途中の失敗で既存のバックアップを切り詰めません。

## 1,000件の確認と残る検証

従来の50件制限を撤廃しました。Ubuntu 24.04の専用コンテナで、固定した1,000件の合成辞書を使い、解析・プレビュー・辞書作成・新しい変換器での候補取得と、GTK画面の検索・編集を確認しています。

R540でのDebugビルド、2 CPU・6 GiB、学習とZenzai無効の単発測定では、JSON解析23 ms、プレビュー30 ms、辞書作成100 msでした。固定した異なる3つの読みによる候補取得は187／1,367／2,534 msで、最初の検索には遅延読込みも含みます。同一操作の分布や速度保証を示す値ではありません。

GTKは別の0.5 CPU・768 MiBの環境で、新しいPythonプロセスを5回起動して描画完了までを測りました。中央値は初回表示654 ms、単語検索38 ms、読み検索78 ms、ヒント検索89 ms、1行編集20 msでした。Swiftを含むアプリ全体の起動時間ではありません。

macOSには1,000件の取込・検索・IDを保った編集のモデル試験を追加しています。macOSの画面描画、ファイル選択、実入力、VoiceOverと、LinuxのOrcaは別途確認が必要です。実配布物の受入結果は[検証結果の記録方法を追加するPR #36](https://github.com/aida0710/azooKey-Desktop/pull/36)に従って記録します。
